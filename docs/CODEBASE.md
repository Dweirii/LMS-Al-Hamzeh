## 1. What the app does

A paid, multi-tenant-ish learning management system for Jordanian universities. Three audiences:

| Audience | Entry point | Capabilities |
|---|---|---|
| Visitor | `/` and `/courses` | Browse published courses, view course detail pages, sign in |
| Student | `/dashboard` | See enrolled courses, watch video lessons, read PDF materials, track progress |
| Admin | `/admin` | Full CRUD on courses/chapters/lessons, upload materials, manage users, instructors, students, view analytics |

Courses are sold individually through Stripe Checkout. Access to lesson content and materials is gated on an
`Enrollment` row with status `Active`, which the Stripe webhook sets after a successful payment.

Content (course thumbnails, lesson videos, material PDFs) lives in a Tigris S3-compatible bucket
(`*.fly.storage.tigris.dev`). Videos and images are served from the bucket host directly; material PDFs are served
through short-lived presigned URLs generated by the app.

## 4. Environment variables

Validated at import time by `lib/env.ts` using `@t3-oss/env-nextjs` + Zod. A missing or malformed variable
fails the build/boot rather than failing at runtime.

**Server-only**

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Postgres connection string (must be a URL) |
| `BETTER_AUTH_SECRET` | Session signing secret |
| `BETTER_AUTH_URL` | Public base URL; also used to build Stripe `success_url` / `cancel_url` |
| `AUTH_GITHUB_ID`, `AUTH_GITHUB_SECRET` | GitHub OAuth app credentials |
| `RESEND_API_KEY` | Sends sign-in OTP emails |
| `ARCJET_KEY` | Arcjet site key |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | Tigris credentials |
| `AWS_ENDPOINT_URL_S3`, `AWS_ENDPOINT_URL_IAM`, `AWS_REGION` | Tigris endpoints/region |
| `STRIPE_SECRET_KEY` | Stripe API key |
| `STRIPE_WEBHOOK_SECRET` | Verifies webhook signatures |

**Client-exposed**

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_S3_BUCKET_NAME_IMAGES` | Bucket name; used both as the S3 `Bucket` and to build public URLs |

Note that the single bucket variable is used for *all* object types (images, videos, materials) despite its name.

## 5. Data model

Defined in `prisma/schema.prisma`, provider `postgresql`. Better-auth's tables are mapped to lowercase names
(`@@map("user")`, `"session"`, `"account"`, `"verification"`, `"material"`); the course-domain tables use Prisma's
default names.

### Auth tables (owned by better-auth)

- **`User`** — `id` (string, supplied by better-auth), `name`, `email` (unique), `emailVerified`, `image`,
  timestamps. Extended with:
  - `stripeCustomerId` (unique, nullable) — set lazily on first checkout
  - `role` (nullable string) — `"admin"`, `"instructor"`, or `null`/other for students
  - `banned`, `banReason`, `banExpires` — from the better-auth `admin` plugin
  - relations: `sessions`, `accounts`, `courses` (courses they created), `instructorCourses` (courses they teach),
    `enrollment`, `lessonProgress`
- **`Session`** — token, expiry, IP, user agent, `impersonatedBy`. Cascades on user delete.
- **`Account`** — OAuth/credential records per provider. Cascades on user delete.
- **`Verification`** — OTP / verification tokens.

### Course domain

- **`Course`** — `id` (uuid), `title`, `description` (TipTap HTML), `fileKey` (thumbnail), `price` (Int, whole
  currency units), `duration` (Int hours), `level` (`CourseLevel`), `stripePriceId` (**unique**), `category`,
  `smallDescription`, `slug` (**unique**), `status` (`CourseStatus`), `university` (`University`, default `UJ`),
  timestamps.
  - `userId` → creator (`User.courses`), cascade delete
  - `instructorId` → optional instructor (`User.instructorCourses`), **no** cascade
  - children: `chapter[]`, `enrollment[]`, `materials[]`
- **`Chapter`** — `title`, `position` (Int, 1-based), `courseId` (cascade), `lessons[]`
- **`Lesson`** — `title`, `description` (optional HTML), `thumbnailKey`, `videoKey`, `position`, `chapterId`
  (cascade), `lessonProgress[]`
- **`Enrollment`** — `amount` (Int), `status` (`EnrollmentStatus`, default `Pending`), `userId` + `courseId`
  (both cascade), `@@unique([userId, courseId])`
- **`LessonProgress`** — `completed` (Boolean, default `false`), `userId` + `lessonId` (both cascade),
  `@@unique([userId, lessonId])`
- **`Material`** — `title`, `fileKey`, `isVisible` (Boolean, default `true`), `courseId` (cascade), timestamps

### Enums

```
University        UJ | PETRA
CourseLevel       Beginner | Intermediate | Advanced
CourseStatus      Draft | Published | Archived
EnrollmentStatus  Pending | Active | Cancelled
```

### Model relationships at a glance

```
User ─┬─< Course (creator: userId)
      ├─< Course (instructor: instructorId, optional)
      ├─< Enrollment >─ Course
      └─< LessonProgress >─ Lesson

Course ──< Chapter ──< Lesson
Course ──< Material
```

### Migration strategy

There is **no `prisma/migrations/` directory**. The schema is applied with `prisma db push`, so there is no
migration history and no reproducible way to replay schema changes. Introducing proper migrations is the single
highest-value schema change to make before further production work.

## 6. Authentication

`lib/auth.ts` configures better-auth:

- **Adapter** — `prismaAdapter(prisma, { provider: "postgresql" })`
- **Social provider** — GitHub (`AUTH_GITHUB_ID` / `AUTH_GITHUB_SECRET`)
- **Plugins**
  - `emailOTP` — sends a one-time code via Resend from `onboarding@resend.dev`.
    Outside production the OTP is also `console.log`ged and a Resend delivery failure is swallowed with a warning,
    so the app can be signed into locally without a verified sending domain. In production a delivery failure throws.
  - `admin()` — supplies `role`, `banned`, `banReason`, `banExpires`, and session impersonation support.

`lib/auth-client.ts` is the browser counterpart: `createAuthClient` with `emailOTPClient()` and `adminClient()`.
Client components read the session reactively with `authClient.useSession()` (see `app/(public)/_components/Navbar.tsx`).

### Sign-in flow

1. `/login` → `LoginForm` offers "Sign in with GitHub" or email.
2. Email path: `authClient.emailOtp.sendVerificationOtp({ email, type: "sign-in" })`, then redirect to
   `/verify-request?email=...`.
3. `/verify-request` collects the 6-digit code with `input-otp` and verifies it.
4. Sign-out is centralized in `hooks/use-singout.ts` (`useSignOut`), which pushes `/` and toasts.

All better-auth HTTP traffic goes through `app/api/auth/[...all]/route.ts`, which wraps the handler in Arcjet
protections (see section 17).

## 7. Authorization model

There is **no `middleware.ts`**. Every protected surface guards itself. Three layers exist, and they are
deliberately redundant.

### Layer 1 — page/layout guards (`app/data/*/require-*.ts`)

Both are wrapped in React's `cache()` so a request pays for at most one session lookup.

- `requireUser()` — returns `session.user`, or `redirect("/login")`.
- `requireAdmin()` — returns the full session; `redirect("/login")` when unauthenticated,
  `redirect("/not-admin")` when `session.user.role !== "admin"`.

`app/admin/layout.tsx` calls `requireAdmin()`, which covers every current and future page under `/admin`.

### Layer 2 — data-function guards

Every function in `app/data/admin/` begins with `await requireAdmin()`, and every student-scoped function in
`app/data/user/` and `app/data/course/` (except the public catalog readers) begins with `await requireUser()`.
So a page that somehow bypassed the layout still cannot read admin data.

Enrollment-scoped readers go further: `getCourseSidebarData` and `getLessonContent` call `notFound()` unless an
`Enrollment` exists for the current user with status `Active`.

### Layer 3 — route-handler guards (`lib/api-auth.ts`)

The `redirect()`-based guards are wrong for `fetch` callers — a 307 to `/login` is not a status the client can act
on. `lib/api-auth.ts` returns JSON instead. Each helper resolves to `{ session }` or `{ error: NextResponse }`,
and callers invoke them *before* their `try/catch` so an auth failure cannot be swallowed into a 500.

| Helper | Rule | Failure |
|---|---|---|
| `requireApiUser()` | any signed-in user | 401 `Authentication required` |
| `requireApiAdmin()` | `role === "admin"` | 403 `Admin access required` |
| `requireCourseAccess(courseId)` | admin, **or** an `Active` enrollment in that course | 403 `Course enrollment required` |

### Roles

Roles are free-form strings on `User.role`:

- `"admin"` — full access to `/admin`
- `"instructor"` — appears in instructor pickers and the instructors console; **grants no elevated access itself**
- `null` or anything else — treated as a student

Students are identified implicitly: admin "students" listings query users who have at least one enrollment.

## 9. Data access layer (`app/data`)

Every file starts with `import "server-only"`, so accidentally importing one into a client component is a build
error rather than a leak. Each module exports a query function and, where the shape is consumed by components, an
inferred type (`AdminCourseType`, `PublicCourseType`, `LessonContentType`, `CourseSidebarDataType`,
`EnrolledCourseType`, `AdminCourseSingularType`, `AdminLessonType`). Components type their props against those
inferred types rather than re-declaring shapes — so widening a `select` automatically widens the component contract.

### `app/data/admin/`

| Function | Returns |
|---|---|
| `requireAdmin()` | Cached admin session guard |
| `adminGetCourses()` | All courses, newest first, with instructor summary |
| `adminGetRecentCourses()` | Same shape, `take: 2` |
| `adminGetCourse(id)` | One course with chapters and lessons; `notFound()` when missing |
| `adminGetLesson(id)` | One lesson; `notFound()` when missing |
| `adminGetDashboardStats()` | `{ totalSignups, totalCustomers, totalCourses, totalLessons }` via one `Promise.all` |
| `adminGetEnrollmentStats()` | Array of 30 `{ date, enrollments }` buckets, zero-filled |
| `getMaterials()`, `getMaterialById(id)`, `getMaterialsByCourseId(courseId)`, `getCourses()` | Materials console reads; each guards with `requireAdmin()` and returns `[]`/`null` on error |

### `app/data/user/`

| Function | Notes |
|---|---|
| `requireUser()` | Cached user guard |
| `getEnrolledCourses()` | `Active` enrollments with nested chapters/lessons and the caller's `lessonProgress`, enough to compute progress client-side |
| `checkIfCourseBought(courseId)` | `boolean`; returns `false` for anonymous visitors instead of redirecting |

### `app/data/course/`

| Function | Guard |
|---|---|
| `getAllCourses()` | None — public, `status: "Published"` only |
| `getIndividualCourse(slug)` | None — public detail page; returns chapters and lesson titles but no `videoKey` |
| `getCourseSidebarData(slug)` | `requireUser()` + `Active` enrollment, else `notFound()` |
| `getLessonContent(lessonId)` | `requireUser()` + `Active` enrollment on the lesson's course, else `notFound()` |

`getIndividualCourse` deliberately omits `videoKey` and `thumbnailKey`, so the public detail page cannot leak
playable media URLs.

## 10. Server actions

All are `"use server"` files colocated with their route, and all return the shared
`ApiResponse = { status: "success" | "error"; message: string }` from `lib/types.ts` (some widen it with a `data`
or `lessonId` field). Callers wrap them in `tryCatch` and surface `message` through Sonner toasts.

### `app/admin/courses/create/actions.ts`

- `getInstructors()` — users with `role: "instructor"`, for the instructor picker.
- `CreateCourse(values)` — `requireAdmin()` → Arcjet fixed window (5/min) → `courseSchema.safeParse` →
  `stripe.products.create` with `default_price_data` (`price * 100`, USD) → `prisma.course.create` storing
  `stripePriceId` and `userId`.

### `app/admin/courses/[courseId]/edit/actions.ts`

- `editCourse(data, courseId)` — `requireAdmin()` → Arcjet → validate → update. **The `where` clause includes
  `userId: user.user.id`**, so an admin can only edit courses they personally created.
- `reorderChapters(courseId, chapters)` / `reorderLessons(chapterId, lessons, courseId)` — position updates inside a
  `$transaction`, then `revalidatePath`.
- `createChapter(values)` / `createLesson(values)` — compute the next `position` from the current max inside a
  transaction. `createLesson` returns the new `lessonId` so the UI can navigate straight to it.
- `deleteChapter` / `deleteLesson` — renumber the surviving siblings to `1..n` and delete, in one transaction.

### `app/admin/courses/[courseId]/delete/actions.ts`

- `deleteCourse(courseId)` — `requireAdmin()` → Arcjet → `prisma.course.delete` (chapters, lessons, enrollments and
  materials cascade) → `revalidatePath("/admin/courses")`.

### `app/admin/courses/[courseId]/[chapterId]/[lessonId]/actions.ts`

- `updateLesson(values, lessonId)` — validates with `lessonSchema` and updates title, description, `thumbnailKey`,
  `videoKey`.

### `app/admin/user-management/actions.ts`

- `banUserAction(id, reason, expires?)`, `unbanUserAction(id)`, `updateUserRoleAction(id, role)` — direct Prisma
  writes to the better-auth fields, then `revalidatePath("/admin/user-management")`.

### `app/admin/instructors/actions.ts`

- `getInstructors()` — instructor summaries with course counts. A instructor's `university` is **derived from their
  first course**, defaulting to `"UJ"` when they have none.
- `getInstructorDetails(id)` — plus per-course enrollment counts.
- `createInstructor(name, email)` — rejects duplicate emails, then inserts a `User` row with
  `id: crypto.randomUUID()`, `role: "instructor"`, `emailVerified: false`. No `Account` row is created; the person
  signs in through the normal email-OTP flow.
- `updateInstructor(id, name, email)` — rejects an email already taken by another user.
- `deleteInstructor(id)` — refuses while the instructor still has assigned courses.
- `getUniversityStats()` — course, instructor and student counts for `UJ` and `PETRA`, hardcoded as two branches.

### `app/admin/students/actions.ts`

- `getStudentsStats()` — totals plus an average completion rate computed in application code by pulling every
  student's enrollments, chapters, lessons and completed-progress rows and looping over them.
- `getStudents()` / `getStudentDetails(id)` — same style, per student.

### `app/(public)/courses/[slug]/actions.ts`

- `enrollInCourseAction(courseId)` — the checkout entry point, detailed in section 13.

### `app/dashboard/[slug]/[lessonId]/actions.ts`

- `markLessonComplete(lessonId, slug)` — `requireUser()` → `lessonProgress.upsert` on the
  `userId_lessonId` unique key → `revalidatePath('/dashboard/{slug}')`.

## 11. HTTP API routes

| Route | Methods | Auth | Purpose |
|---|---|---|---|
| `/api/auth/[...all]` | `GET`, `POST` | n/a | better-auth handler; `POST` is wrapped in Arcjet |
| `/api/webhook/stripe` | `POST` | Stripe signature | Activates enrollments on `checkout.session.completed` |
| `/api/s3/upload` | `POST` | `requireAdmin()` + Arcjet 5/min | Returns a presigned `PutObject` URL (6-minute expiry) and its object key |
| `/api/s3/delete` | `DELETE` | `requireAdmin()` + Arcjet 5/min | Deletes an object by key |
| `/api/materials/upload` | `POST` | `requireApiAdmin()` | Multipart upload: streams the file to S3 under `materials/{courseId}/{timestamp}-{name}` and creates the `Material` row |
| `/api/materials/[id]` | `GET`, `DELETE` | `GET`: `requireCourseAccess`; `DELETE`: `requireApiAdmin` | Fetch material metadata; delete the S3 object then the row |
| `/api/materials/[id]/visibility` | `PATCH` | `requireApiAdmin()` | Toggles `isVisible` |
| `/api/materials/[id]/view` | `GET` | `requireCourseAccess()` | Returns `{ url }` — a 1-hour presigned GET, or the stored absolute URL |
| `/api/courses/[courseId]/materials` | `GET` | inline session + `Active` enrollment check | Lists visible materials for an enrolled student (`id`, `title`, `createdAt` only) |

Notes on the materials routes, which carry most of the access-control weight:

- `/api/materials/[id]/view` looks up the material *first* so it can resolve `courseId`, then calls
  `requireCourseAccess(material.courseId)`. Without that gate, anyone holding a material id could download paid
  content. It additionally 404s a non-visible material for non-admins — hiding a material actually hides it.
- Responses from `/view` carry `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: strict-origin-when-cross-origin` and no-store cache headers. The URL is returned as JSON rather
  than a redirect, because Chrome blocks cross-origin redirects inside the sandboxed iframe the viewer uses.
- `fileKey` may hold either an S3 object key or an absolute `http(s)` URL (seeded/imported rows). Both `/view` and
  `useConstructUrl` detect the latter with `/^https?:\/\//i` and pass it through instead of presigning a key that
  does not exist in the bucket.
- The old unauthenticated collection endpoint `app/api/materials/route.ts` (public `GET` list + public `POST`
  upload) has been **deleted** on this branch. Nothing in the UI referenced it; `MaterialsHeader` posts to
  `/api/materials/upload`.

Client call sites, for reference:

```
components/file-uploader/Uploader.tsx        → POST /api/s3/upload, DELETE /api/s3/delete
app/admin/materials/.../MaterialsHeader.tsx  → POST /api/materials/upload
app/admin/materials/.../MaterialCard.tsx     → PATCH /api/materials/{id}/visibility, DELETE /api/materials/{id}
app/admin/materials/[id]/.../MaterialDetails → GET /api/materials/{id}, GET /api/materials/{id}/view
app/dashboard/[slug]/.../DashboardMaterials  → GET /api/courses/{courseId}/materials, GET /api/materials/{id}/view
app/(public)/courses/[slug]/.../SecurePDFViewer → GET /api/materials/{id}/view
```

## 12. File storage and upload flows

`lib/S3Client.ts` creates one `S3Client` with `region: "auto"`, the Tigris endpoint, and
`forcePathStyle: false`. It is `server-only`.

There are two distinct upload paths, and knowing which one you are looking at matters:

### A. Course thumbnails and lesson videos — presigned PUT (browser → S3 directly)

`components/file-uploader/Uploader.tsx`:

1. `react-dropzone` accepts one image or video.
2. `POST /api/s3/upload` with `{ fileName, contentType, size, isImage }`. The route validates with Zod, applies the
   Arcjet rate limit keyed on the admin's user id, generates `key = ${uuidv4()}-${fileName}`, and returns
   `{ presignedUrl, key }` with a 360-second expiry.
3. The browser `PUT`s the file to `presignedUrl` with an `XMLHttpRequest` so it can report progress.
4. The resulting `key` is written into the form field (`fileKey`, `thumbnailKey`, `videoKey`).
5. Removing a file calls `DELETE /api/s3/delete` with `{ key }`.

Because the bytes never pass through the Next.js server, this path is not subject to serverless body-size limits.

### B. Course materials — server-side upload (browser → Next.js → S3)

`POST /api/materials/upload` receives `multipart/form-data`, buffers the whole file
(`Buffer.from(await file.arrayBuffer())`), `PutObject`s it under `materials/{courseId}/{Date.now()}-{name}`, and
creates the `Material` row. This is simpler but holds the entire file in server memory and is bounded by the
platform's request-body limit (roughly 4.5 MB on Vercel serverless functions). Large PDFs will fail here.

### Reading objects back

- Images and videos: `hooks/use-construct-url.ts` builds
  `https://{NEXT_PUBLIC_S3_BUCKET_NAME_IMAGES}.fly.storage.tigris.dev/{key}` — a public bucket URL, no signature.
- Materials: always through `/api/materials/[id]/view`, which returns a 1-hour presigned URL.
- `next.config.ts` allow-lists `lms-alhamzeh.fly.storage.tigris.dev` for `next/image`, and adds
  `picsum.photos`, `fastly.picsum.photos` and `images.unsplash.com` **only outside production**, so locally seeded
  sample content renders in dev while the deployed app still trusts only the storage bucket.

## 13. Payments and enrollment

### Product creation

Creating a course creates a Stripe **product** with an inline `default_price_data` in USD at `price * 100` cents.
The resulting price id is stored on `Course.stripePriceId` (unique). Editing a course's `price` afterwards updates
only the database row — **the Stripe price is not updated**, so checkout continues to charge the original amount.

### Checkout

`enrollInCourseAction(courseId)` in `app/(public)/courses/[slug]/actions.ts`:

1. `requireUser()`.
2. Arcjet fixed window, 5/min, keyed on the user id.
3. Load the course (`id`, `title`, `price`, `slug`, `stripePriceId`).
4. Resolve the Stripe customer: reuse `user.stripeCustomerId`, otherwise `stripe.customers.create` with
   `metadata.userId` and persist the id.
5. In a `prisma.$transaction`:
   - If an `Active` enrollment already exists, return early with "You are already enrolled in this Course".
   - Otherwise create a new `Pending` enrollment, or reset an existing non-active one to `Pending`.
   - Create a Stripe Checkout Session (`mode: "payment"`, one line item at `stripePriceId`,
     `success_url` / `cancel_url` built from `BETTER_AUTH_URL`) with
     `metadata: { userId, courseId, enrollmentId }`.
6. `redirect(checkoutUrl)` — deliberately outside the `try/catch`, since Next.js implements `redirect()` by
   throwing.

`Stripe.errors.StripeError` is mapped to a "Payment system error" message; anything else to "Failed to enroll in
course".

### Webhook

`app/api/webhook/stripe/route.ts`:

1. Read the raw body, verify `Stripe-Signature` against `STRIPE_WEBHOOK_SECRET`; a bad signature returns 400.
2. On `checkout.session.completed`, read `metadata.courseId` and the Stripe `customer` id, look the user up by
   `stripeCustomerId`, and update the enrollment identified by `metadata.enrollmentId` to
   `status: "Active"` with `amount: session.amount_total`.
3. Always returns `204`-style `new Response(null, { status: 200 })` at the end.

Missing `courseId` or an unknown customer `throw`, which surfaces as a 500 and causes Stripe to retry.

### Gating

Once `Enrollment.status === "Active"`:

- `checkIfCourseBought` flips the course detail CTA from "Enroll" to "Watch Course".
- `getCourseSidebarData` and `getLessonContent` stop calling `notFound()`.
- `requireCourseAccess` starts allowing material views.

## 14. Progress tracking

- Completion is stored per `(userId, lessonId)` in `LessonProgress`, upserted by `markLessonComplete`.

## 15. Course materials subsystem

Materials are per-course files (in practice PDFs) uploaded by admins, stored in S3, and exposed to enrolled
students through a protected viewer. There is no `Material`-to-`Lesson` relationship; materials hang off the course.

**Admin side**

- `/admin/materials` lists every material (`MaterialsList` → `MaterialCard`) with the course it belongs to.
- `MaterialsHeader` holds the upload dialog: title, course `Select` populated by `getCourses()`, file input; posts
  to `/api/materials/upload`, then `router.refresh()`.
- `MaterialCard` toggles visibility (`PATCH .../visibility`) and deletes (`DELETE /api/materials/{id}`).
- `/admin/materials/[id]` (`MaterialDetails`) fetches metadata then `/view`, and previews the file inline.

**Student side**

- `/dashboard/[slug]/materials` (`DashboardMaterials`) lists visible materials via
  `/api/courses/{courseId}/materials` — a response that intentionally contains no `fileKey`.
- Opening one calls `/api/materials/{id}/view` and renders the result in `SecurePDFViewer`.
- `CourseMaterialsSection` on the public course page shows a teaser of what the course includes.

**Deletion semantics** — `DELETE /api/materials/[id]` attempts the S3 delete first and logs but ignores a failure,
then deletes the database row, so a storage error cannot leave an undeletable record.

## 16. Content protection

The app treats course media as paid content and layers several deterrents. They raise the effort bar; none is a
cryptographic guarantee, and that should be stated plainly to stakeholders.

### Video (`app/dashboard/[slug]/[lessonId]/_components/CourseContent.tsx`)

The `VideoPlayer` is defined inside `CourseContent` and:

- renders a native `<video>` with `controls`, `controlsList="nodownload"`, `preload="metadata"`, `playsInline`, and
  a poster built from `thumbnailKey`;
- installs a `keydown` listener that `preventDefault`s `F12`, `Ctrl+Shift+I/J/C`, `Ctrl+U`, and the macOS
  `Cmd+Option+I/J/C` equivalents;
- polls every second comparing `window.outerWidth/Height` against `innerWidth/Height` with a 160px threshold to
  guess whether DevTools is open;
- intercepts `contextmenu` when the target is inside a `<video>`;
- on any of those signals shows a copyright warning toast, throttled to once per 10 seconds via a `useRef`
  timestamp so the warning cannot become a toast storm;
- falls back to a "This lesson does not have a video yet" placeholder when `videoKey` is empty.

Video URLs themselves are public bucket URLs, not signed — a determined user who reads the DOM can fetch the file.

### PDF (`components/ui/SecurePDFViewer.tsx`)

- Renders page-by-page onto a `<canvas>` with `pdfjs-dist`, so the browser's native PDF UI (with its download and
  print buttons) never appears.
- Custom controls only: previous/next page, zoom in/out, rotate, retry-on-error.
- `pdfjs-dist` is imported **lazily** through a module-level memoized promise:

  ```ts
  let pdfjsPromise: Promise<PdfJs> | null = null;
  function loadPdfJs() {
    if (!pdfjsPromise) {
      pdfjsPromise = import("pdfjs-dist").then((lib) => {
        lib.GlobalWorkerOptions.workerSrc = "/pdf.worker.min.js";
        return lib;
      });
    }
    return pdfjsPromise;
  }
  ```

  A static import crashes server-side rendering because pdf.js touches `DOMMatrix` while its module initializes,
  even inside a `"use client"` component. The worker file is served from `public/pdf.worker.min.js`.
- Source URLs are 1-hour presigned GETs fetched on demand, so a copied URL expires.

A second, smaller copy of this component exists at `app/(public)/courses/[slug]/_components/SecurePDFViewer.tsx`
(181 lines vs 358) — see [technical debt](#24-known-issues-and-technical-debt).

## 17. Abuse protection (Arcjet)

`lib/arcjet.ts` exports a base client keyed on a `"fingerprint"` characteristic with a single `shield({ mode: "LIVE" })`
rule, and re-exports the rule builders so call sites import everything from one place. It is `server-only`.

Protected surfaces:

| Surface | Rules |
|---|---|
| `POST /api/auth/[...all]` | On `/api/auth/sign-up` with an email in the body: `protectSignup` — blocks `DISPOSABLE`/`INVALID`/`NO_MX_RECORDS` emails, disallows all bots, sliding window 5 per 2 minutes. Otherwise `detectBot`, plus `slidingWindow` on other sign-up shapes. Fingerprint is the user id when signed in, else the client IP via `@arcjet/ip` |
| `POST /api/s3/upload`, `DELETE /api/s3/delete` | `fixedWindow` 5/minute, fingerprint = admin user id |
| `CreateCourse`, `editCourse`, `deleteCourse`, `enrollInCourseAction` | `fixedWindow` 5/minute, fingerprint = user id, via `request()` from `@arcjet/next` |

Denials are translated into user-facing messages: rate limit → "You have been blocked due to rate limiting",
bot → "You are a bot! if this is a mistake contact our support", and for auth specifically, per-reason email
messages with a 400, 429 for rate limits, and 403 otherwise.

The auth route currently `console.log`s every Arcjet decision, and the S3 routes return the placeholder error
string `"dudde not good"` with a 429.

## 20. Validation schemas

`lib/zodSchemas.ts` is the single source of form validation, and its constant arrays double as the option lists
rendered in the admin `Select`s — so a new level or category is a one-line change in one file.

```ts
courseLevels     = ["Beginner", "Intermediate", "Advanced"]
courseStatus     = ["Draft", "Published", "Archived"]
universities     = ["UJ", "PETRA"]
courseCategories = ["Development", "Business", "Finance", "IT & Software",
                    "Office Productivity", "Personal Development", "Design",
                    "Marketing", "Health & Fitness", "Music", "Teaching & Academics"]
```

| Schema | Fields |
|---|---|
| `courseSchema` | `title` (3–100), `description` (≥3), `fileKey` (≥1), `price` (coerced, ≥1), `duration` (coerced, 1–500), `level`, `category`, `smallDescription` (3–200), `slug` (≥3), `status`, `instructorId` (uuid, optional), `university` |
| `chapterSchema` | `name` (≥3), `courseId` (uuid) |
| `lessonSchema` | `name` (≥3), `chapterId` (uuid), `courseId` (uuid), `description` (≥3, optional), `videoKey` (optional), `thumbnailKey` (optional) |

Exported inference types: `CourseSchemaType`, `ChapterSchemaType`, `LessonSchemaType`.

These same enum arrays must stay in step with the Prisma enums — they are duplicated, not generated.
`slugify` is used in `CourseCreationForm` to generate the slug from the title.

Every server action re-validates with `safeParse` even though the client form already validated; client validation
is a UX affordance, not a trust boundary.

## 22. Build and deployment

- Target platform is Vercel. `@prisma/nextjs-monorepo-workaround-plugin` is a dependency, and

## 24. Known issues and technical debt

Ordered roughly by impact. Each is a factual observation about the current code.

### Correctness and security

1. **No migration history.** `prisma/migrations/` does not exist; the schema is applied with `db push`. Schema
   changes are not reproducible or reviewable, and production drift is undetectable.
2. **`editCourse` is scoped to the creator.** The update's `where` includes `userId: user.user.id`, so admin A
   cannot edit a course created by admin B — the update silently affects zero rows and the action reports failure.
3. **Stripe prices go stale.** `CreateCourse` creates the Stripe price once. `editCourse` updates `Course.price`
   in the database without touching Stripe, so checkout keeps charging the original amount and the displayed price
   diverges from the charged price.
4. **Webhook throws instead of responding.** Missing `metadata.courseId` or an unknown `stripeCustomerId` throws,
   producing a 500 and an indefinite Stripe retry loop. The handler also trusts `metadata.enrollmentId` without
   checking it belongs to the resolved user.
5. **Materials upload runs through the server.** `POST /api/materials/upload` buffers the whole file in memory and
   is bounded by the platform body-size limit (~4.5 MB on Vercel). Course videos avoid this by using presigned PUTs;
   materials should too.
6. **Video URLs are unsigned.** Lesson video and thumbnail URLs are public bucket URLs. The DevTools/right-click
   deterrents in `CourseContent` do not prevent anyone who reads the DOM from fetching the file directly. If real
   protection is required, videos need signed URLs or a token-gated streaming path.
7. **Deleting a course leaves storage and Stripe behind.** `deleteCourse` removes database rows (cascading to
   chapters, lessons, enrollments and materials) but never deletes the S3 objects or archives the Stripe product,
   so objects and products accumulate.
8. **`/api/s3/upload` does not restrict content type or size.** The Zod schema requires `contentType` and `size` to
   be present but validates neither, and `isImage` is parsed and then ignored. Any admin can presign an upload of
   any type or size.
9. **Role checks are string comparisons.** `role === "admin"` is spread across the codebase with no shared
   constant or enum, and `"instructor"` grants nothing, so the role's meaning is purely presentational today.

### Consistency and duplication

10. **Two `SecurePDFViewer` components** — `components/ui/SecurePDFViewer.tsx` (358 lines) and
    `app/(public)/courses/[slug]/_components/SecurePDFViewer.tsx` (181 lines). They will drift.
11. **Two `getInstructors()` functions** — one in `app/admin/courses/create/actions.ts`, one in
    `app/admin/instructors/actions.ts`, returning different shapes.
12. **Two `CoursesFilters` components** with near-identical logic, one for the public catalog and one for admin.
13. **`/api/courses/[courseId]/materials` hand-rolls its authorization** inline instead of calling
    `requireCourseAccess` from `lib/api-auth.ts`, which does exactly the same thing.
14. **Enum values are duplicated** between `prisma/schema.prisma` and `lib/zodSchemas.ts` with no generation step.
15. **University is an enum, not a table.** Adding a third university requires a schema change, a Zod change, and
    edits to `getUniversityStats()`, which is hardcoded as two parallel branches for `UJ` and `PETRA`.
16. **An instructor's university is inferred** from their first course, defaulting to `"UJ"`. An instructor teaching
    at both universities, or none, is misreported.

### Performance

17. **Admin student statistics are computed in application code.** `getStudentsStats()` and `getStudents()` load
    every student's enrollments, every chapter, every lesson id and every completed-progress row, then loop. This is
    O(all lessons × all students) per page view and should be aggregate SQL.
18. **`/courses` is `force-dynamic` and unfiltered server-side.** All published courses are serialized to the client
    on every request and filtered in the browser.
19. **No database indexes beyond the implicit ones.** There are no explicit `@@index` declarations; lookups by
    `Course.slug`, `Course.status` and `Material.courseId` rely on whatever Prisma creates for unique constraints
    and foreign keys.

### Cosmetic

20. `dummyEnrollmentData` in `components/sidebar/chart-area-interactive.tsx` is dead code, kept alive by a
    file-level `eslint-disable` for unused variables.
21. `DashboardAppSidebar` carries unused `navClouds`/`documents` scaffolding from the shadcn template, and the
    admin sidebar's "Settings" and "Get Help" links point at `#`.
22. Placeholder error strings reach users: `"dudde not good"` (S3 routes, 429).
23. Typos in user-facing copy and filenames: `hooks/use-singout.ts`, "Singed out Successfully",
    "created succesfully", "alredy enrolled".
24. `app/api/auth/[...all]/route.ts` logs every Arcjet decision to the server console on every auth request.
25. Several admin data functions swallow errors and return `[]` or `null` (`app/data/admin/admin-get-materials.ts`),
    so a database failure renders as an empty list rather than an error.

## 25. Glossary of conventions

Patterns worth following when extending the codebase:

- **`import "server-only"` at the top of every server module** in `app/data/` and the sensitive `lib/` files
  (`arcjet`, `stripe`, `S3Client`, `api-auth`). Makes a client-side import a build error.
- **Guard first, then `try/catch`.** Authorization runs before the `try` block so a 401/403 cannot be swallowed
  into a 500.
- **Redirect guards for pages, JSON guards for routes.** `requireAdmin`/`requireUser` for navigations;
  `requireApiAdmin`/`requireApiUser`/`requireCourseAccess` for `fetch` callers.
- **`cache()` around session guards** so a request resolves the session at most once.
- **Return `ApiResponse` from every server action**, and consume it through `tryCatch` + a Sonner toast.
- **Validate with Zod inside the action**, never trusting the client form's validation.
- **Derive types from queries** (`Awaited<ReturnType<typeof fn>>`) rather than hand-writing DTOs, so widening a
  `select` widens the component contract automatically.
- **`revalidatePath` after every mutation** that a server-rendered page displays.
- **Colocate** route-specific components in `_components/` and route-specific actions in `actions.ts`.
- **`position` fields are 1-based and renumbered on delete**, inside a transaction, so gaps never appear.
- **Object keys may be absolute URLs.** Anything that turns a `fileKey` into a URL must handle the
  `/^https?:\/\//i` case (see `useConstructUrl` and `/api/materials/[id]/view`).
